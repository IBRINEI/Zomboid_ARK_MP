Чистое повторное подключение после установки исправления подтвердило итоговый контракт:
клиент получил 847/847 записей (194 main, 653 emergency), `dirty=false` и
`refreshPending=false`. Реальный round trip
`slice4-42.20-final-reconnect-001` прошёл как client `requestState` → server validation
→ client `stateSnapshot`. Серверная ревизия продолжила увеличиваться минутным тиком,
поэтому текущая server revision была на единицу новее уже принятого snapshot; correlation
ID ответа совпал.

Перезапуск подтвердил отсутствие дублированных ArkMP callbacks: по одному
`LoadGridsquare`, `EveryOneMinute`, `OnClientCommand`, `OnServerStarted` и
`OnInitGlobalModData`. Повторяющиеся `NetworkZombieMind: goal character is not set`
при наличии Bandits2 и предупреждения импортёра skeleton не исходят из Lua-файлов
Bunker Campaign; они остаются отдельной совместимостью зависимости.

После correlation-маркера серверный лог не содержал ошибок. В клиентском логе продолжил
появляться только `NetworkZombieMind`; Lua stack trace или ошибка Bunker Campaign не
зафиксированы. QA-мир оставлен в рабочем состоянии корреляцией
`slice4-42.20-final-restore-power-001`: основной генератор заправлен и запущен, grid,
main lighting, ventilation, water и heating получили генераторное питание; отопление
`operating=true`, `powerAllocated=true`. Backup остался выключенным и исчерпанным.

Ограничения этого прогона: отрицательный gate обычного пользователя подтверждён в
предыдущем runtime-сеансе и automated tests, но в текущем рестарт-сеансе игрок имел
admin access; межклиентская репликация не проверена. Без отложенного Java patch
server-authoritative тепловая симуляция работает, но её температура не подменяет
ванильный `getAirTemperatureForSquare`.
