# Техническое задание: кооперативный bunker-survival мод для Project Zomboid Build 42

## 1. Общая задача

Нужно разработать мод для **Project Zomboid Build 42**, рассчитанный прежде всего на кооперативную многопользовательскую кампанию.

Рабочая концепция:

> Кооперативный bunker-survival, вдохновлённый модом The Ark, но с более глубокой технологической прогрессией, исследованиями, развитием экспедиционного транспорта, случайно размещаемыми ключевыми предметами и инструментами гейммастера.

Игроки живут в подземном бункере и поддерживают его системы в рабочем состоянии. Поверхность заражена, холодна и опасна. Для выходов требуются защитные костюмы, противогазы, расходуемые фильтры, лекарства, обогрев и подготовленный транспорт.

Главная долгосрочная цель — не просто выживать, а постепенно превращать аварийный бункер в автономную технологическую базу, которая позволяет проводить всё более дальние и сложные экспедиции.

Мод не должен быть копией The Ark. The Ark используется как дизайн-референс для:

* радиационной поверхности;
* ядерной зимы;
* фильтров;
* противогазов;
* заражения предметов;
* дезактивации;
* вентиляции;
* CO₂;
* водоснабжения;
* генераторов;
* поломок систем;
* квестов по восстановлению инфраструктуры.

Не использовать без разрешения автора The Ark:

* его исходный код;
* карту;
* ассеты;
* модели;
* тексты;
* сюжет;
* персонажей;
* интерфейсы.

Все механики реализовать самостоятельно.

# 2. Ключевые особенности проекта

Мод должен включать:

1. Серверно-синхронизированное состояние бункера.
2. Несколько взаимосвязанных систем жизнеобеспечения.
3. Загрязнённую поверхность.
4. Разные типы внешней угрозы.
5. Противогазы и расходуемые фильтры.
6. Защитные костюмы и их повреждение.
7. Загрязнение одежды, предметов, персонажей и транспорта.
8. Дезактивацию при возвращении в бункер.
9. Экстремальную температуру.
10. Исследовательскую систему.
11. Модернизацию систем бункера.
12. Уникальные предметы, открывающие новые механики.
13. Последовательно развиваемый экспедиционный автомобиль.
14. Удалённые экспедиционные точки.
15. Инструменты гейммастера.
16. Возможность играть без постоянного участия гейммастера.
17. Несколько вариантов стратегического финала кампании.

# 3. Основной игровой цикл

Основной цикл должен выглядеть так:

1. Получить информацию о потенциальной цели.
2. Оценить состояние бункера.
3. Выбрать цель экспедиции.
4. Подготовить оборудование.
5. Выбрать маршрут и транспорт.
6. Выйти на поверхность.
7. Преодолеть внешние угрозы.
8. Найти данные, образцы или оборудование.
9. Вернуться в бункер.
10. Пройти дезактивацию.
11. Проанализировать находки.
12. Завершить исследование.
13. Улучшить бункер, экипировку или транспорт.
14. Получить доступ к более удалённым целям.

После полноценной игровой сессии игроки должны получать хотя бы одно из следующего:

* новую механику;
* новую технологию;
* важную информацию;
* координаты объекта;
* новую ветку исследования;
* новый маршрут;
* изменение состояния мира;
* крупный компонент для будущего проекта.

Не строить прогрессию только вокруг накопления ресурсов.

# 4. Отличие от The Ark

The Ark используется как основа философии выживания, но новый проект должен отличаться следующим:

| The Ark                                     | Новый мод                                 |
| ------------------------------------------- | ----------------------------------------- |
| Преимущественно одиночная сюжетная кампания | Кооперативная серверная кампания          |
| Линейная цепочка заданий                    | Частично нелинейная прогрессия            |
| Фиксированные системы бункера               | Модернизируемые системы                   |
| NPC ведут сюжет                             | Игроки и GM управляют развитием           |
| Фиксированное расположение многих предметов | Частично случайное расположение           |
| Обслуживание существующей базы              | Восстановление и технологическое развитие |
| Один крупный транспортный квест             | Несколько уровней развития транспорта     |
| Scripted events                             | Серверные события и GM Director           |
| Один сюжетный финал                         | Несколько стратегических финалов          |

# 5. Основные принципы дизайна

## 5.1. Не превращать игру в обслуживание таймеров

Обслуживание должно создавать решения, а не рутину.

Плохой вариант:

* раз в час менять фильтр;
* раз в час заправлять генератор;
* раз в час чистить воду;
* раз в час чинить вентиляцию.

Хороший вариант:

* выбирать, какие системы сейчас запитать;
* отключать отдельные помещения;
* выбирать между ремонтом и экспедицией;
* временно переходить на аварийный режим;
* решать проблему несколькими способами.

Рекомендуемая доля обслуживания базы:

* примерно 15–25% игрового времени;
* остальное — исследования, экспедиции, логистика, подготовка и развитие.

## 5.2. Каждая крупная проблема должна иметь несколько решений

Пример: отказ вентиляции.

Возможные решения:

1. Починить внешний воздухозаборник.
2. Перейти на внутреннюю рециркуляцию.
3. Запечатать часть помещений.
4. Носить противогазы внутри бункера.
5. Отключить лабораторию и перенаправить питание.
6. Временно эвакуироваться в резервное убежище.

## 5.3. Улучшения должны менять игровой процесс

Плохое улучшение:

* фильтр служит на 5% дольше.

Хорошее улучшение:

* фильтры можно частично регенерировать;
* автомобиль получает герметичную кабину;
* игроки видят прогноз заражённых бурь;
* система заранее обнаруживает поломки;
* можно анализировать образцы в дороге;
* появляется возможность строить промежуточные базы.

Процентные бонусы допустимы, но не должны быть основной наградой.

# 6. Внешние угрозы

Не использовать одну абстрактную шкалу «радиации». Разделить опасность на несколько независимых компонентов.

## 6.1. Загрязнённый воздух

Воздействует через дыхание.

Защита:

* респиратор;
* противогаз;
* фильтр;
* герметичная кабина;
* вентиляция укрытия;
* замкнутый дыхательный контур.

Параметры:

* концентрация загрязнения;
* тип загрязняющего вещества;
* целостность маски;
* качество фильтра;
* физическая нагрузка;
* герметичность одежды;
* открытые двери и окна транспорта.

## 6.2. Поверхностное загрязнение

Оседает на:

* одежде;
* обуви;
* оружии;
* рюкзаках;
* найденных предметах;
* автомобиле;
* контейнерах;
* наружных элементах бункера.

Заражённые предметы могут загрязнять:

* шлюз;
* склад;
* транспорт;
* жилые помещения;
* других игроков.

Необходимы:

* грязная зона;
* чистая зона;
* дезактивационный шлюз;
* отдельный склад образцов;
* герметичные контейнеры.

## 6.3. Внешнее излучение

Противогаз от него не защищает.

Защита:

* сокращение времени пребывания;
* расстояние;
* укрытие;
* экранирование;
* правильный маршрут;
* защищённый транспорт;
* точный дозиметр.

Некоторые зоны должны оставаться опасными даже при наличии хороших фильтров.

## 6.4. Температура

Поверхность должна быть ощутимо холодной или, в отдельных сценариях, чрезмерно жаркой.

Температура не должна полностью контриться одной одеждой.

Учитывать:

* качество одежды;
* слои;
* ветер;
* влажность;
* мокрую одежду;
* время на поверхности;
* физическую активность;
* голод;
* горячую пищу;
* химические грелки;
* обогрев транспорта;
* температуру двигателя;
* наличие временного убежища.

Возможные эффекты:

* снижение ловкости;
* замедление действий;
* дрожь;
* повышенный расход калорий;
* обморожение;
* невозможность долго ремонтировать машину на улице;
* проблемы с запуском двигателя;
* ускоренная разрядка аккумулятора.

## 6.5. Радиоактивные и погодные события

Примеры:

* заражённая метель;
* изменение ветра;
* выпадение радиоактивной пыли;
* внезапное падение температуры;
* пылевая буря;
* кратковременное снижение загрязнения;
* локальный выброс с промышленного объекта.

# 7. Медицинские средства

Не делать йодид калия универсальным средством от любой радиации.

Разделить медикаменты:

## 7.1. Йодид калия

Используется только против определённого типа радиоактивного загрязнения.

Эффект:

* снижает последствия воздействия радиоактивного йода;
* действует ограниченное время;
* не лечит уже полученную общую дозу;
* не защищает от внешнего излучения.

## 7.2. Вымышленные радиопротекторы

Можно добавить редкие инъекционные препараты:

* временно снижают скорость накопления повреждений;
* имеют побочные эффекты;
* требуют исследований;
* не являются полноценной защитой;
* используются для аварийных экспедиций.

## 7.3. Симптоматическое лечение

Добавить:

* препараты от тошноты;
* стимуляторы;
* противоожоговые средства;
* восстановительные растворы;
* лечение химических поражений;
* средства от обморожения.

# 8. Системы бункера

Основные модули:

1. Энергетика.
2. Вентиляция.
3. Отопление и термоконтур.
4. Вода.
5. Дезактивация.
6. Лаборатория.
7. Мастерская.
8. Гараж.
9. Радиоцентр.
10. Медицинский блок.
11. Серверная.
12. Теплица.

Для MVP обязательны первые восемь.

## 8.1. Энергетика

Функции:

* генераторы;
* резервное питание;
* распределение мощности;
* аккумуляторные блоки;
* аварийный режим;
* подключение внешнего топливного резервуара.

Параметры:

* состояние генератора;
* запас топлива;
* текущая нагрузка;
* максимальная мощность;
* запас аккумуляторов;
* температура;
* риск аварии.

Игроки должны выбирать, какие системы включить.

Пример:

* отопление;
* лаборатория;
* вентиляция;
* очистка воды;
* мастерская.

Одновременно может не хватать мощности на всё.

## 8.2. Вентиляция

Параметры:

* состояние наружного воздухозаборника;
* ресурс фильтра;
* скорость циркуляции;
* уровень CO₂;
* наружная загрязнённость;
* герметичность помещений.

Режимы:

* наружная фильтрация;
* внутренняя рециркуляция;
* аварийная вентиляция;
* полное запечатывание;
* продувка шлюза.

## 8.3. Отопление

Параметры:

* температура помещений;
* состояние теплообменника;
* энергопотребление;
* теплопотери;
* состояние труб;
* доступность топлива.

Повреждение системы не должно мгновенно убивать игроков. Температура должна падать постепенно.

## 8.4. Вода

Параметры:

* запас;
* загрязнение;
* состояние насоса;
* ресурс фильтрующего материала;
* производительность;
* энергопотребление.

Возможные источники:

* подземная скважина;
* внешние резервуары;
* снег;
* загрязнённая вода;
* найденные запасы.

## 8.5. Дезактивация

Функции:

* очистка игроков;
* очистка одежды;
* очистка предметов;
* очистка транспорта;
* очистка образцов для безопасного хранения.

Расходники:

* вода;
* электричество;
* NBC-реагенты;
* фильтры;
* моющие вещества.

Должны существовать:

* полноценный автоматический цикл;
* дешёвый ручной цикл;
* аварийный упрощённый цикл.

## 8.6. Лаборатория

Функции:

* анализ образцов;
* проведение исследований;
* восстановление данных;
* определение природы загрязнения;
* открытие технологий;
* медицинские исследования;
* анализ фильтров.

Уровни лаборатории:

1. Базовая.
2. Химическая.
3. Радиометрическая.
4. Биологическая.
5. Полевая автоматизированная.

## 8.7. Мастерская

Функции:

* ремонт оборудования;
* производство расходников;
* восстановление фильтров;
* создание компонентов;
* модификация транспорта;
* ремонт модулей бункера.

## 8.8. Гараж

Функции:

* капитальный ремонт;
* установка экспедиционных модулей;
* дезактивация транспорта;
* зарядка аккумуляторов;
* хранение топлива;
* диагностика герметичности.

# 9. Состояния систем

Каждая система должна иметь минимум три состояния:

## Рабочее

Полный функционал.

## Деградировавшее

Система работает, но:

* потребляет больше ресурсов;
* имеет пониженную производительность;
* создаёт дополнительные риски;
* может отказать.

## Аварийное

Система отключена или почти не работает, но это не мгновенный конец кампании.

Пример:

```lua
status = "operational"
status = "degraded"
status = "critical"
status = "offline"
```

## 10.2. Образцы

* ткани заражённых;
* кровь;
* растения;

## 10.3. Компоненты

# 11. Примеры исследований

## Анализ загрязнённой пыли

Требует:

* несколько использованных фильтров;
* образец пыли;
* лабораторную посуду;
* работающий анализатор.

Открывает:

* определение типа загрязнения;
* более эффективный тип фильтра;
* правильное медицинское средство.

## Регенерация фильтров

Требует:

* каталитическую матрицу;
* химические реактивы;
* промышленную документацию;
* улучшенную мастерскую.

Открывает:

* частичное восстановление использованных фильтров;
* производство регенерируемых кассет.

## Замкнутая вентиляция

Требует:

* контроллер вентиляции;
* компрессор;
* датчики CO₂;
* инженерную документацию.

Открывает:

* внутреннюю рециркуляцию;
* уменьшенный расход внешних фильтров;
* запечатывание отдельных помещений.

## Радиометрическая карта

Требует:

* данные нескольких станций;
* серверный модуль;
* калибровочный источник;
* исправный радиоцентр.

Открывает:

* отображение уровней опасности;
* прогноз движения заражённых облаков;
* безопасные временные окна.

## Холодный запуск двигателя

Требует:

* военный контроллер;
* утеплённый аккумуляторный модуль;
* документацию;
* испытания на автомобиле.

Открывает:

* запуск в экстремальный холод;
* подогрев двигателя;
* уменьшение расхода аккумулятора.

## Герметичная кабина

Требует:

* компрессор;
* авиационные уплотнители;
* контроллер давления;
* фильтрующий блок.

Открывает:

* отдельный воздушный контур машины;
* использование автомобильного фильтра;
* снижение расхода персональных фильтров.

## Автоматическая диагностика

Требует:

* серверный модуль;
* промышленные датчики;
* программное обеспечение;
* сеть кабелей.

Открывает:

* предупреждение о поломках;
* журнал состояния систем;
* удалённый мониторинг.

## Мобильная лаборатория

Требует:

* экспедиционную машину;
* лабораторный модуль;
* аккумулятор;
* герметичный контейнер.

Открывает:

* анализ простых образцов в дороге;
* предварительную идентификацию;
* безопасное хранение.

---

# 12. Уникальные предметы

Уникальные предметы должны открывать новые механики, а не давать только числовые бонусы.

Примеры:

| Предмет                       | Возможное место         | Открываемая механика     |
| ----------------------------- | ----------------------- | ------------------------ |
| Военный контроллер вентиляции | Командный бункер        | Герметизация помещений   |
| Калибровочный источник        | Университет             | Точные дозиметры         |
| Каталитическая матрица        | Химический завод        | Регенерация фильтров     |
| Блок управления двигателем    | Военный автопарк        | Экспедиционный транспорт |
| Архив метеостанции            | Удалённая станция       | Прогноз бурь             |
| Прототипный теплообменник     | Энергетический объект   | Улучшенное отопление     |
| Карта коммуникаций            | Муниципальный архив     | Подземные маршруты       |
| Серверный модуль              | Исследовательский центр | Автоматизация бункера    |
| Авиационные уплотнители       | Аэродром                | Герметичная кабина       |
| Медицинский анализатор        | Госпиталь               | Продвинутые препараты    |
| Спектрометр                   | Лаборатория             | Анализ типов загрязнения |
| Военный ключ доступа          | Случайный объект        | Доступ к секретным зонам |

На одну кампанию достаточно приблизительно 12–16 уникальных предметов.

---

# 13. Размещение уникальных предметов

Использовать два типа размещения.

## 13.1. Логически фиксированные объекты

Игроки знают общий тип места:

* теплообменник находится на энергетическом объекте;
* медицинский анализатор находится в госпитале;
* авиационные компоненты находятся на аэродроме.

Но конкретная комната, контейнер или здание могут меняться.

## 13.2. Рандомизированные предметы

При создании мира сервер выбирает одно место из набора допустимых точек.

Пример:

```lua
ArtifactSpawnGroups = {
    MilitaryController = {
        "MilitaryBase_A_Room12",
        "MilitaryBase_B_Bunker03",
        "Checkpoint_C_CommandTrailer"
    }
}
```

Игроки должны получать подсказки:

* документы;
* радиосигналы;
* карты;
* архивы;
* показания свидетелей;
* координаты;
* фрагменты кодов доступа.

Нельзя создавать ситуацию, где потеря одного уникального предмета навсегда блокирует кампанию.

Для каждого критического предмета должен быть:

* резервный экземпляр;
* альтернативный квест;
* возможность восстановить предмет;
* GM-команда для возврата;
* аварийный обходной путь.

---

# 14. Прогрессия по зонам

Карта должна быть условно разделена на кольца сложности.

## Зона 0: вокруг бункера

Опасность:

* умеренное загрязнение;
* сильный холод;
* небольшие группы заражённых.

Ресурсы:

* еда;
* обычные инструменты;
* топливо;
* базовые фильтры;
* лекарства;
* детали.

Цель:

* запустить базовые системы бункера.

## Зона 1: ближайшие населённые пункты

Требования:

* противогазы;
* тёплая одежда;
* простая дезактивация;
* обычный транспорт.

Ресурсы:

* электроника;
* лабораторная посуда;
* книги;
* автомобильные детали;
* карты;
* документы.

## Зона 2: промышленные районы

Опасность:

* высокое загрязнение;
* токсичные помещения;
* промышленные выбросы;
* сложные здания.

Ресурсы:

* насосы;
* компрессоры;
* химикаты;
* фильтры;
* промышленные контроллеры;
* генераторы.

## Зона 3: научные и военные объекты

Требования:

* улучшенные костюмы;
* качественные фильтры;
* герметичный транспорт;
* промежуточные базы.

Ресурсы:

* уникальные предметы;
* военные контроллеры;
* экспериментальные препараты;
* секретные документы;
* серверные модули.

## Зона 4: глубокая заражённая область

Требования:

* экспедиционная машина;
* мобильное отопление;
* несколько запасных фильтров;
* дальняя связь;
* временные базы;
* многодневный запас.

Экспедиция должна состоять из нескольких этапов:

1. Доехать до промежуточного объекта.
2. Восстановить его питание.
3. Создать временную базу.
4. Дождаться подходящей погоды.
5. Проехать в глубокую зону.
6. Получить ключевой предмет.
7. Вернуться другим маршрутом.

---

# 15. Развитие транспорта

Транспорт должен быть одной из центральных линий прогрессии.

## Этап 1. Обычный автомобиль

Особенности:

* не герметичен;
* фильтры персонажей расходуются в салоне;
* плохо запускается на холоде;
* быстро теряет тепло;
* малый запас ресурсов.

Используется для ближайших экспедиций.

## Этап 2. Разведывательный автомобиль

Модули:

* дополнительный аккумулятор;
* автономный отопитель;
* радиостанция;
* внешний дозиметр;
* крепления для канистр;
* утепление двигателя;
* контейнер для грязного снаряжения.

## Этап 3. Герметичный экспедиционный автомобиль

Модули:

* компрессор;
* фильтр кабины;
* датчик давления;
* герметизация дверей;
* усиленные окна;
* воздушный шлюз;
* система контроля загрязнения;
* внешний воздухозаборник.

Механики:

* персональные фильтры почти не расходуются при закрытой кабине;
* автомобильный фильтр расходуется отдельно;
* открытая дверь нарушает давление;
* разбитое окно отключает защиту;
* повреждение кузова снижает герметичность;
* фильтр быстрее расходуется при высокой загрязнённости.

## Этап 4. Мобильная база

Модули:

* спальное место;
* верстак;
* резервное питание;
* отопление;
* хранилище образцов;
* простая лаборатория;
* связь;
* запас воды;
* аварийная дезактивация.

Ограничения:

* нельзя выполнять самые сложные исследования;
* нельзя проводить капитальный ремонт;
* нельзя бесконечно жить вдали от бункера;
* требуется возвращение на основную базу.

---

# 16. Отдельный топливный транспортный майлстоун

Добавить ранний или средний проект, вдохновлённый топливозаправщиком The Ark.

Игроки должны:

1. Получить информацию о машине.
2. Найти её.
3. Починить.
4. Заправить.
5. Расчистить маршрут.
6. Привести к бункеру.
7. Подключить к наружному топливному узлу.

Результат:

* большой запас топлива;
* уменьшение давления ранней игры;
* возможность запускать лабораторию и отопление одновременно;
* открытие следующих проектов.

Топливозаправщик не должен быть основной экспедиционной машиной.

---

# 17. Промежуточные базы

Игроки должны иметь возможность восстанавливать удалённые объекты:

* метеостанции;
* гаражи;
* насосные станции;
* радиорелейные пункты;
* маленькие убежища;
* технические тоннели;
* склады;
* лаборатории.

Промежуточная база может предоставлять:

* отопление;
* сохранение;
* зарядку;
* укрытие;
* временную фильтрацию;
* связь;
* ремонт;
* склад;
* точку маршрута.

Базы требуют периодического обслуживания, но не должны создавать множество постоянных таймеров.

---

# 18. Роль гейммастера

Гейммастер выступает как Director кампании.

Он не должен вручную контролировать каждого заражённого.

Основные функции:

* запуск событий;
* выдача радиосообщений;
* управление погодой;
* изменение состояния отдельных зон;
* размещение или перенос уникальных предметов;
* создание альтернативных путей прогресса;
* управление враждебными группами;
* исправление сломанных сюжетных цепочек;
* изменение активности заражённых;
* управление глобальным уровнем угрозы.

## Рекомендуемый ритм GM

За одну сессию:

* не более одного крупного осложнения;
* одна новая важная улика;
* одно последствие прошлого решения;
* не более двух активных аварий бункера.

Не создавать постоянные волны нападений без причины.

---

# 19. Примеры GM-событий

## Технические

* отказ внешнего воздухозаборника;
* утечка воды;
* перегрев генератора;
* повреждение шлюза;
* отказ отопления;
* короткое замыкание;
* загрязнение склада;
* неисправность автомобильного фильтра.

## Погодные

* заражённая метель;
* резкое падение температуры;
* изменение ветра;
* краткое безопасное окно;
* выпадение токсичной пыли.

## Экспедиционные

* исчезновение сигнала станции;
* перекрытие дороги;
* обрушение тоннеля;
* появление новой орды;
* пожар на объекте;
* обнаружение чужой группы;
* перемещение ценного груза.

## Сюжетные

* неизвестный радиосигнал;
* расшифровка части архива;
* координаты секретного объекта;
* ложный сигнал бедствия;
* требование обмена;
* обнаружение следов другой экспедиции.

---

# 20. GM-панель

Создать отдельный интерфейс, доступный только администраторам или игрокам с GM-правами.

Разделы:

## Бункер

* состояние систем;
* запас ресурсов;
* уровень загрязнения;
* включение и отключение модулей;
* аварийный ремонт;
* журнал событий.

## Мир

* уровень заражения зон;
* погода;
* температура;
* активность заражённых;
* состояние удалённых объектов;
* открытие координат.

## События

* запуск бури;
* поломка системы;
* радиосигнал;
* миграция;
* авария;
* нападение;
* открытие маршрута.

## Исследования

* открыть проект;
* добавить данные;
* добавить образец;
* завершить исследование;
* вернуть потерянный предмет.

## Артефакты

* показать текущее местоположение;
* переместить;
* создать резервный экземпляр;
* пометить найденным.

## Транспорт

* диагностика герметичности;
* повреждение модуля;
* восстановление сюжетного автомобиля;
* управление состоянием фильтра.

---

# 21. Работа без GM

Мод должен быть играбельным без постоянного гейммастера.

Для этого нужен автоматический Director.

Параметры:

* текущий уровень угрозы;
* число игроков;
* состояние бункера;
* длительность с последнего события;
* число активных аварий;
* среднее количество ресурсов;
* прогресс исследований;
* удалённость текущей цели.

Director не должен запускать крупные события слишком часто.

Пример:

```lua
DirectorState = {
    threat = 0.35,
    lastMajorEventHours = 72,
    activeCrises = 1,
    pressure = 0.42,
    campaignTier = 2
}
```

Ограничения:

* не более одной крупной аварии одновременно;
* не запускать нападение сразу после тяжёлой экспедиции;
* не уничтожать критические предметы;
* не запускать случайную необратимую смерть бункера;
* учитывать число игроков.

---

# 22. Многопользовательская архитектура

Сервер должен быть авторитетным.

Клиент не должен самостоятельно решать:

* завершено ли исследование;
* сколько ресурса осталось в фильтре;
* исправна ли система;
* найден ли артефакт;
* открыт ли проект;
* является ли помещение безопасным;
* сколько топлива в центральном резервуаре.

Клиент:

* отображает интерфейс;
* отправляет запрос;
* проигрывает эффекты;
* показывает состояние.

Сервер:

* проверяет условия;
* изменяет данные;
* удаляет предметы;
* сохраняет состояние;
* синхронизирует клиентов.

---

# 25. Фильтры

Фильтры должны иметь:

* тип;
* ресурс;
* качество;
* класс защиты;
* загрязнение;
* повреждение;
* возможность регенерации;
* максимальное число регенераций;
* технологический уровень.

Пример данных:

```lua
FilterData = {
    filterType = "standard_gas_mask",
    remaining = 0.82,
    protectionClass = 1,
    contamination = 0.12,
    damaged = false,
    regenerationCount = 0,
    maxRegenerations = 2
}
```

Формула расхода:

```text
расход =
базовая скорость
× загрязнённость зоны
× физическая нагрузка
× повреждение маски
× коэффициент качества
× коэффициент технологии
```

Не обновлять ресурс каждый кадр.

Выполнять расчёт:

* раз в несколько игровых секунд;
* при смене зоны;
* при надевании маски;
* при снятии маски;
* при входе в транспорт;
* при открытии двери;
* при повреждении экипировки.

---

# 26. Защитный костюм

Костюм должен иметь:

* герметичность;
* состояние;
* загрязнение;
* теплоизоляцию;
* устойчивость к повреждениям;
* совместимость с маской;
* возможность ремонта.

Прокол или разрыв:

* снижает защиту;
* ускоряет загрязнение персонажа;
* увеличивает расход фильтра;
* может быть временно заклеен ремонтным комплектом.

---

# 27. Загрязнение предметов

Каждый поддерживаемый предмет может хранить:

```lua
ContaminationData = {
    surface = 0.25,
    internal = 0.0,
    contaminationType = "fallout_dust",
    sealed = false
}
```

Распространение загрязнения должно быть ограниченным и оптимизированным.

Не пересчитывать взаимодействие каждого предмета с каждым предметом.

Использовать событийную модель:

* предмет положили в контейнер;
* игрок вошёл в чистую зону;
* предмет прошёл дезактивацию;
* дверь шлюза открыта;
* транспорт вошёл в гараж.

---


# 29. Пользовательские интерфейсы

Обязательные окна:

## 29.1. Пульт бункера

Показывает:

* питание;
* нагрузку;
* температуру;
* вентиляцию;
* CO₂;
* запас воды;
* загрязнение;
* состояние систем;
* активные аварии;
* прогноз времени работы.

Позволяет:

* включать и отключать системы;
* менять режим вентиляции;
* запускать дезактивацию;
* распределять энергию;
* активировать аварийный режим.

## 29.2. Лаборатория

Показывает:

* доступные исследования;
* требования;
* найденные компоненты;
* время;
* потребление энергии;

# 31. Структура кампании

## Акт I: аварийный запуск

Состояние:

* вентиляция деградирована;
* отопление нестабильно;
* лаборатория не работает;
* запас фильтров ограничен;
* вода требует очистки.

Цели:

* восстановить энергетику;
* починить вентиляцию;
* обеспечить воду;
* найти первые защитные комплекты.

Финал:

* бункер способен пережить несколько дней автономно.

## Акт II: исследование катастрофы

Цели:

* собирать образцы;
* анализировать пыль;
* восстановить лабораторию;
* открыть регенерацию фильтров;
* получить карту заражения.

Финал:

* игроки понимают структуру внешней угрозы.

## Акт III: топливо и транспорт

Цели:

* найти топливозаправщик;
* восстановить гараж;
* создать разведывательную машину;
* найти контроллер двигателя.

Финал:

* открывается дальняя экспедиционная зона.

## Акт IV: сеть удалённых объектов

Цели:

* восстановить метеостанцию;
* активировать радиорелейный пункт;
* создать промежуточную базу;
* наладить удалённую связь.

Финал:

* возможны многодневные экспедиции.

## Акт V: глубокая зона

Цели:

* собрать герметичную машину;
* проникнуть в научный или военный объект;
* найти ключевые архивы;
* определить источник катастрофы.

## Акт VI: стратегический выбор

Варианты финала:

* полностью автономизировать бункер;
* создать безопасный коридор;
* эвакуировать выживших;
* связаться с другим убежищем;
* запустить сеть очистки;
* отключить источник заражения;
* покинуть регион на экспедиционном транспорте.

# 32. Баланс

Основные правила:

1. Базовые фильтры должны быть воспроизводимыми.
2. Улучшенные фильтры требуют редких компонентов.
3. Уникальные предметы не должны расходоваться навсегда без предупреждения.
4. Смерть игрока не должна уничтожать общие исследования.
5. Потеря машины не должна безвозвратно завершать кампанию.
6. Ремонт транспорта нужен после нескольких экспедиций, а не каждой поездки.
7. Одежда помогает против холода, но не отменяет его.
8. Чем дальше цель, тем важнее должна быть открываемая механика.
9. Не запускать несколько тяжёлых событий подряд.
10. Не делать нападения главным источником сложности.
11. Не использовать необъяснимые мгновенные смерти.
12. Всегда показывать причину ухудшения состояния персонажа.
13. Критические показатели должны иметь предупреждения.
14. Должны существовать аварийные решения.
15. Не создавать невидимых обязательных таймеров.

---

# 33. Обратная связь игроку

Игрок должен понимать:

* почему расходуется фильтр;
* почему растёт загрязнение;
* почему холодно;
* почему не работает система;
* какой компонент отсутствует;
* что изменилось после исследования;
* почему машина потеряла герметичность;
* откуда пришёл сигнал;
* насколько срочно событие.

Использовать:

* звуковые сигналы;
* сообщения NOAH-подобного компьютера;
* индикаторы;
* журнал событий;
* радиосообщения;
* диагностические отчёты;
* понятные иконки.

Не использовать имя NOAH, если оно слишком явно связано с The Ark. Создать собственное название центральной системы.

# 34. Нефункциональные требования

## Производительность

* не выполнять тяжёлые расчёты каждый кадр;
* использовать периодические обновления;
* использовать зоны;
* кэшировать результаты;
* не сканировать всю карту;
* не перебирать все предметы мира;
* не синхронизировать всё состояние при каждом изменении;
* отправлять только изменившиеся данные.

## Надёжность

* сохранять состояние кампании;
* поддерживать миграцию версии данных;
* вести лог;
* обрабатывать отсутствие объекта;
* восстанавливать потерянные ссылки на транспорт;
* не ломать сохранение при удалении необязательного предмета.

## Совместимость

* минимизировать overrides базовых файлов;
* использовать собственные namespaces;
* не изменять глобальные таблицы без необходимости;
* документировать несовместимости;
* отделить карту от основного кода;
* сделать основные системы независимыми от конкретной карты.

# 37. MVP

Первая играбельная версия должна содержать:

* один бункер;
* четыре основные системы:

  * питание;
  * вентиляция;
  * отопление;
  * дезактивация;
* один тип загрязнённой поверхности;
* один тип противогаза;
* два типа фильтров;
* загрязнение персонажей и одежды;
* холод;
* шесть исследований;
* восемь уникальных предметов;
* пять важных точек экспедиции;
* один топливозаправщик;
* один модернизируемый автомобиль;
* пять серверных событий;
* базовую GM-панель;
* сохранение состояния;
* поддержку минимум четырёх игроков.

Не включать в первый MVP:

* сложную биологическую систему;
* десятки типов радиации;
* большую сюжетную кампанию;

* множество автомобилей;
* полноценную мобильную базу;
* десятки интерфейсов.

# 38. Acceptance criteria для MVP

MVP считается успешным, если:

1. Сервер корректно сохраняет состояние бункера.
2. После перезапуска сервера состояние восстанавливается.
3. Два клиента видят одинаковое состояние.
4. Клиент не может самостоятельно завершить исследование.
5. Фильтр расходуется только при нахождении в опасной зоне.
6. При снятии маски персонаж получает воздействие.
7. Повреждение маски увеличивает воздействие.
8. Загрязнённый предмет можно очистить.
9. Игрок может принести ресурсы и завершить исследование.
10. Исследование открывает новую механику.
11. Поломка вентиляции создаёт решаемую проблему.
12. Бункер не погибает мгновенно при одной аварии.
13. Автомобильный фильтр работает отдельно от персонального.
14. Разбитое окно нарушает герметичность автомобиля.
15. GM может запустить и остановить событие.
16. Критический артефакт можно восстановить через GM-панель.
17. Система не создаёт существенных задержек на сервере.
18. В журнале отображаются причины аварий и изменений.

# 39. Первое задание для Codex

Сначала не пытайся написать весь мод.

Выполни следующие шаги:

1. Изучи доступные API Project Zomboid Build 42 в локальном окружении проекта.
2. Создай структуру мода.
3. Создай `docs/ARCHITECTURE.md`.
4. Опиши клиент-серверную модель.
5. Реализуй версионируемое глобальное состояние кампании.
6. Реализуй сохранение и загрузку.
7. Реализуй тестовый модуль вентиляции.
8. Реализуй простое окно состояния вентиляции.
9. Реализуй серверную команду включения и выключения вентиляции.
10. Добавь журналирование.
11. Добавь защиту от некорректных данных клиента.
12. Подготовь инструкции по ручному тестированию в multiplayer.

Тестовый модуль вентиляции должен хранить:

```lua
ventilation = {
    enabled = true,
    condition = 1.0,
    status = "operational",
    filterRemaining = 1.0,
    co2 = 400,
    externalContamination = 0.0,
    recirculationUnlocked = false
}
```

Начальная логика:

* если вентиляция включена и фильтр исправен, CO₂ уменьшается;
* если вентиляция выключена, CO₂ постепенно растёт;
* если наружное загрязнение высокое, фильтр расходуется быстрее;
* при нулевом фильтре наружное загрязнение начинает попадать внутрь;
* клиент получает состояние от сервера;
* клиент не может напрямую изменить значения;
* администратор может включить и выключить систему;
* состояние сохраняется после перезапуска.

Создать кооперативный мод для Project Zomboid Build 42, который берёт survival-основу The Ark — заражённую поверхность, бункер, фильтры, дезактивацию, холод, вентиляцию, воду и поломки — и развивает её в серверную survival-кампанию с:

* технологическими исследованиями;
* модернизацией бункера;
* случайными уникальными предметами;
* дальними экспедициями;
* последовательным развитием транспорта;
* промежуточными базами;
* несколькими вариантами прохождения;
* автоматическим Director;
* инструментами гейммастера.

Главное ощущение от игры:

> В начале игроки боятся выйти из аварийного бункера на несколько часов. В конце они управляют сетью безопасных пунктов, герметичным экспедиционным транспортом и способны проводить многодневные операции в глубокой заражённой зоне.
