# Zomboid ARK MP — состояние проекта

## Назначение и границы

Zomboid ARK MP — самостоятельная server-authoritative реализация систем бункера The ARK для Project Zomboid Build 42.20. Это не тонкий сетевой патч: геометрия и часть ассетов переиспользуются, а состояние, проверки, сетевой обмен и сохранение переписаны под dedicated server.

Текущий релизный предел — локальный сервер и один клиент. Успешная приёмка даёт статус `Build 42.20 local one-client QA passed / multiplayer provisional`. Статус `multiplayer accepted` запрещён до отдельного прогона минимум с двумя одновременно подключёнными клиентами.

## Архитектурный контракт

- Сервер — единственный владелец изменяемого состояния. Клиент отправляет намерение; сервер повторно проверяет игрока, положение, оборудование, ресурсы и права.
- Клиент хранит только UI/cache последнего server snapshot. Он не выполняет authoritative mutation.
- Команды, которые расходуют ресурсы, используют correlation/transaction ID. Повторный ID возвращает прежний результат без повторного списания.
- Общие Lua-файлы загружаются в двух независимых VM и при hot reload перезагружаются отдельно на сервере и клиенте.
- Persistent state нормализуется через schema/defaults при загрузке. Новые поля должны иметь миграцию или безопасное значение по умолчанию.
- Ошибка строительства комнаты латчится с фазой и координатами; дальнейший nil-доступ не маскирует первопричину.

## Порядок server tick

Действующий фиксированный порядок: готовность/миграция состояния → вход и строительство → физическая энергетическая сеть → логическая энергетика и shedding → освещение → вода → вентиляция и breach → климат/отопление → загрязнение/дезактивация → публикация revision/snapshot. Сетевой broadcast запрещён до `OnServerStarted` и готовности UDP engine.

## Готовые системы

- Два логических генератора, шесть потребителей с приоритетами, батарея, аварийный режим, топливо/охлаждайка/смазка и износ.
- Шесть скрытых `IsoGenerator` bridges для ванильного `haveElectricity()`; 194 основных и 653 аварийных источника света.
- Пять режимов вентиляции, составные контуры помещений, CO2 по объёму, фильтр, четыре воздухозаборника, шлюзовая продувка и breach по четырём дверям.
- Waterpipes как владелец физической воды; clean/dirty storage, идемпотентное потребление, tainted water и ремонт насоса.
- Поверхностное загрязнение/перенос, маски и фильтры, загрязнённые предметы/трупы, внешняя и бункерная мойка, циклы дезактивации.
- Вход и server-side строительство уровней -4/-5/-7 и 22 комнат; admin QA.

## Кандидат из slice 4

Климат выпадения осадков, тепловая инерция и потери, перемешивание комнат, усиленные потери при breach, шесть физических отопительных узлов, поломки, диагностика и ремонты. Цель отопления меняется только рядом с исправным контроллером; остальные системы панели доступны игроку внутри бункера и совпадают с серверной валидацией.

## Исключено и отложено

NOAH, Emma/NPC AI, исходная временная шкала, миссии, диалоги, кошмары, PlaceEvents и финалы имеют статус `excluded_local_mvp` либо `deferred_rewrite`, а не «невозможно в MP». Research engine, компетенции, экспедиции, транспорт, GM/Director и рабочие специализированные модули ещё не начаты. Радиационная медицина требует отдельной server-authoritative переработки. Cryogenic Winter в оригинале The ARK не интегрирован.

## Версии

Разработка и QA фиксированы на Project Zomboid 42.20. Все активные `mod.info` имеют `versionMin=42.20`. `BunkerCampaignThermalJava` написан под ZombieBuddy 3.0.0-alpha, тогда как активный runtime остаётся на API 2.3.x; мост выключен, базовые системы не должны от него зависеть. Experimental HTTP работает через документированный Windows/JDK 25 compatibility hotfix от официального 2.3.3.
